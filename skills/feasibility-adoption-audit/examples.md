# 採用盤點示例

下列均為示意，不是實際專案證據；每次盤點仍須引用當前可得來源與版本。

## 成功不等於已實作
E001 成功驗證 A；正式程式沒有 A 的接入證據。若有當前明確未落地紀錄並完成有界來源查核，記 A 未採用；若只查少量檔案或來源不可得，記不確定。不從成功狀態或搜尋未命中推導採用程度。

## 部分採用與排除
E002 包含 A、B、C。A 有正式程式、接入及對應行為測試結果；B 的實作待辦仍有效；C 有明確不採用決策。分列 A 已採用、B 未採用、C 已排除，並引用各自證據。若只 A 的部分行為完成，拆出剩餘行為或記部分採用；不把整個 E002 當成全有或全無。

## 重寫與等效既有能力
E003 的同步示範被正式非同步版本重寫。對照必要行為、原決策、接入及驗證，不要求同名檔案。若只能證明正式來源已有等效能力，卻無法確認由 E003 採用，報告「能力已滿足；實驗來源關係不確定」，不發明搬移歷史。

## 沒有 tracker 的舊實驗
從 README 問題、結論與來源版本辨識能力，報告中標「本輪補建識別」。檢查正式行為及接入，不要求先建立 tracker。只因缺 tracker 或名稱相似，不能判未採用／已採用。不能讀取某批實驗時，明示未覆蓋集合，不能說整個專案已無未採用驗證。

## tracker 與正式來源衝突
紀錄說已採用，但程式已移除或必要入口停用，不能沿用舊分類。確認版本與歷史；證據不足或互相衝突時記不確定，列出需核對的移除決策、接入與驗證證據。唯讀報告不直接修 tracker，也不自動補回程式。

## 實驗失敗與任務完成
E004 假設被否定，驗證任務已完成；不能因此將它記已排除，除非有明確不採用決策。E005 無法判定真實依賴，即使 README 已完成，也不證明正式採用或未採用。分開保留驗證結果、採用程度、證據缺口與報告完成判斷。

## 報告與後續動作
盤點讀到缺失的邊界測試結果時，記所需證據，不自行執行測試或修改正式來源。使用者另外要求保存報告時，只按已授權位置寫報告；這不授權更新 tracker、實驗歷史或進行採用實作。
