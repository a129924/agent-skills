# Purpose
在明確查核範圍與版本內，說明驗證所支持的能力是否已進入正式實作。以證據找出未完成項，不把缺少採用紀錄當作未採用，也不把驗證成功當作已實作。

# Trigger / When to use
- 使用：想找尚未進入正式實作的驗證成果、追查部分採用或確認既有採用紀錄是否符合現況。
- 排除：設計或執行新實驗、寫入採用紀錄、正式程式採用實作、發布或重開鎖定決策。
- 可盤點文件／原始碼即可回答的驗證，不限有編號實驗或成功狀態的項目。

# Inputs
- 使用者指定的驗證／文件集合或目標專案，以及可得版本。
- 可得正式需求、鎖定決策、正式來源與接入位置。
- 可得採用紀錄、變更歷史與行為驗證證據；沒有 tracker 仍可盤點。

# Process
1. **界定範圍。**先唯讀確認來源集合、正式來源及接入範圍、版本／快照、排除範圍與觀察日期。來源不限實驗目錄；未指定集合時，依當前專案明示本輪可查的集合，不假稱涵蓋其他專案。`src-implementation` 是泛稱，按專案規範及實際用途定位。無法確定目標專案或重大範圍歧義時，先查可得情境，再詢問必要問題。
2. **拆出能力／決策。**由驗證的問題、結論、條件、來源程式與既有決策辨識能力，不把整個實驗當作單一可搬移套件。保留驗證的四狀態及任務完成語意；它們不是採用狀態。舊資料識別可於報告中補建，明標本輪補建，不寫回歷史。
3. **逐項比對。**查採用紀錄、正式程式、實際接入、相關行為驗證及必要歷史。引用版本與位置，分開觀察事實、推論與缺口；對重寫按行為和決策查，不只比檔名或相似程式。既有等效能力可證明需求已滿足，但無來源證據不能宣稱由該實驗採用。紀錄與程式衝突時，不盲信 tracker。
4. **有證據分類。**使用下表，程度與採用方式分開。部分採用列出完成／剩餘能力；必要接入或行為證據不足，不因程式存在標已採用。缺 tracker、搜尋未命中或只查一小部分，均不能直接判未採用。資料過期、對應不明或證據衝突標不確定，指出足以解除不確定的查核。
5. **輸出唯讀報告。**用[模板](templates/adoption-audit.md)列範圍、版本、逐項分類與依據，突出未採用、部分採用及不確定項。指出明確排除項及理由，避免反覆當作待辦。來源未能讀取或集合未完整列舉時，明示報告覆蓋限制；「查到的項目都已採用」不代表全專案沒有待辦。輸出至對話，不寫程式、tracker 或報告檔；另有明確寫檔要求時，依原權限只保存報告，不修改被盤點來源。

| 採用程度 | 必要依據 |
| --- | --- |
| 已採用 | 所選能力有正式實作、實際接入及對應行為驗證證據。 |
| 部分採用 | 有完成部分的證據，且能明列尚未完成的能力／接入。 |
| 未採用 | 有明確未落地證據，或足夠且有界的正式來源／接入查核，並交代查核範圍。 |
| 已排除 | 有明確不採用決策、理由及來源；不能由實驗失敗自行推定。 |
| 不確定 | 覆蓋不足、來源或版本不明、證據不足／衝突，或無法確認對應。 |

# Examples
- 正例：E001 有 A、B；A 有正式接入和驗證證據，B 有尚未實作的明確紀錄。分項列 A 已採用、B 未採用，標出查核版本與位置。
- 反例：所有沒有 adoption tracker 的實驗都標未採用；或將名稱相同的正式檔案直接當成已接入證據。
- 重寫、排除、舊資料與證據衝突情境見 [examples.md](examples.md)。

# Outputs
- 有界、可追溯的能力／決策採用盤點，包含五分類、具體證據與查核限制。
- 未採用／部分採用／不確定清單、已排除原因及下一個所需證據；不自動變成實作任務或更改既有決策。

# Validation
## Required Checks
- 來源集合、正式範圍、版本、排除與觀察日期明確，未冒稱完整覆蓋。
- 每項分類有對應證據或明確缺口；重寫、等效能力及來源關係分開。
- 驗證四狀態、驗證任務完成、採用五分類與本輪報告完成判斷分開。
- 沒有修改程式、tracker 或實驗歷史；沒有以無紀錄／無搜尋結果直接判未採用。

## Quality Checks (best effort)
- 將缺口寫成可執行的下一個查核，不以模糊「待確認」掩蓋未知。

## On Soft Fail
可讀部分仍能有用時採 `SOFT FAIL`，本輪處理標 `INCOMPLETE` 並交付有界報告，缺證據項標不確定。若連目標或範圍都無法識別，繼續會產生誤導時標 `BLOCKED`，停止受影響分類，不虛構盤點。

# Failure Handling
## Missing Context
先查當前專案、來源、紀錄與正式程式；缺 tracker 不阻擋全部盤點。列明不可得來源或版本及其影響，避免把漏查範圍當成空集合。

## Ambiguous Requirement
只在查證後仍無法解決、且會實質改變盤點意義的範圍／目標歧義時詢問。可安全界定的子集合先明示限制並報告，不補造來源關係。

## Execution Limitation
無法讀取必要來源或歷史時，保留可得證據及限制；未執行測試不能捏造驗證通過。盤點不自動執行測試、建置或外部操作來補證據，需要新的驗證時列為下一步並沿原授權／流程處理。

# Boundaries
- 唯讀盤點不是採用批准，不修改正式程式、tracker 或實驗 README。
- 不新增必經 phase、approval、runtime orchestration 或工具依賴。
- 不要求另一個 skill 或新 tracker 已安裝；舊紀錄與來源足夠時直接查核。
- 報告完成可包含不確定項，但不能將它們冒稱已解除或整個實作已完成。
