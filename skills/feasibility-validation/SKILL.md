# Purpose
主動引導技術問題收斂、最小實驗設計與證據判讀，將有範圍的結論交回原決策位置。README 是紀錄工具，不能用填答案取代設計與判讀。

# Trigger / When to use
- 使用：存在影響實作選擇的技術未知，需要確認行為、限制或依賴條件。
- 排除：一般功能實作、例行建置或測試、沒有決策影響的探索、正式程式採用審查、已鎖定決策的直接改寫。
- 先唯讀查官方文件與原始碼；足以回答就留下來源、版本、適用條件與決策影響，不建立實驗。只有答案必須透過執行確認，且影響實作選擇時才進實驗。

# Inputs
- 已知主要問題與實作決策，以及可得背景；使用者不必預先提供假設或判準，agent 依據文件／原始碼與決策主動設計。
- 可得文件／原始碼依據、目標環境、輸入、依賴假設及未知條件。
- 已有判準（若有）與可用的執行／寫入權限；缺少技術判準時由 agent 提出可觀察的成功／失敗／無法判定條件。
- 已知投入界線（時間、嘗試或資源）；缺少時依情境提出有依據的有限投入建議與停止條件，在既有授權內設計，不默認無限投入。無法從情境確認且涉及重大投入或授權時才澄清，不將建議冒充使用者要求。

# Process
全程主動維持五項判斷：**需要實驗嗎、到底驗證什麼、最小實驗怎麼做、怎樣算成立、證據支持到哪裡**。依據官方文件／原始碼與已知決策主動提出假設、操作、區辨輸入及事前判準；可設計的技術項不等同猜造需求，不杜撰業務需求或觀測結果。

1. **定義問題。** 先查文件／原始碼，能回答則直接記錄依據並返回決策。否則依已知決策與來源主動收斂一個主要問題並提出有依據的假設，連結不同結果的實作選擇；問題或決策未知時先查可得事實，僅無法解決且會實質改變業務需求或決策的歧義才詢問並停止依賴動作；標示獨立依賴假設，必要時拆成另一實驗。
2. **設定判準。** 缺少判準時由 agent 根據問題、來源與擬議的區辨操作／輸入主動提出成功、失敗與無法判定的可觀察條件，在執行前固定，不要求使用者填判準。依情境提出有限投入上限與停止條件；只有無法確認的重大投入或授權界線才詢問並停止依賴動作。主要假設判準不能由 build 成功或 test 通過代替。不得事後換判準來配合結果；新問題需另立並保留原紀錄。
3. **設計最小實驗。** 選擇能真正區分成立／不成立的操作、輸入與觀察，交代每者如何對應判準。工具與語言自由；減少無關功能，勿刪除關鍵區辨條件。確認權限與前置條件後，在目標專案的 `experiments/` 檢查 E001、E002 等編號及歷史占用，選未使用編號並用 [模板](templates/experiment-readme.md) 建立 `experiments/E001/README.md` 等紀錄。重用歷史須明確說明相同問題、環境與證據適用性；未授權不得覆寫既有實驗。
4. **執行並保存證據。** 僅在既有授權範圍內執行；集中必要程式、設定及可公開資料，排除建置產物、秘密與非公開資料。記錄日期、環境版本、前置條件、實際輸入、指令、觀察及證據位置。模擬資料／依賴須明標；達到投入上限或停止條件就停止，保留部分證據，不冒充完整執行。
5. **判讀結果。** 按事前判準分類，分開觀察事實與推論，檢查依賴假設與證據缺口。建置／測試成功只是對應操作的證據。模擬或有限輸入只支持已驗證條件，不能外推真實依賴或普遍保證。
6. **寫回紀錄。** 完成八段 README，在「是否成功」分別記錄四狀態與本輪驗證任務完成否及理由；結論寫回原決策位置。足以支持決策的證據可完成本輪，即使假設被否定。無法判定時，只有明確交代原因、缺少證據及決策限制才可完成本輪紀錄；受阻決策仍不能推進。

# Examples
- 正例：驗證增量 UTF-8 解碼，把三位元組字元切在區塊邊界，逐批輸入並比較 flush 後完整輸出，依事前判準決定是否採用。
- 反例：整檔解碼成功或 build 通過，就宣稱跨區塊解碼假設成立；操作沒有測到關鍵條件。
- 各分支的輸入、判準及證據限制見 [examples.md](examples.md)。

# Outputs
- 文件即可回答：來源、版本／位置、事實、推論、限制及決策影響，不需實驗目錄。
- 必須實驗：一個編號目錄，含八段 README、必要可重現素材及證據；列明狀態、任務完成否、缺口、依賴與決策影響。
- 四個實驗狀態僅為「未執行／成功／失敗／無法判定」；成功／失敗表示假設依判準成立／不成立，不表示驗證任務完成／未完成。

# Validation
## Required Checks
- 文件優先判斷有依據；進實驗時執行必要性與決策影響都明確。
- 一個主要問題連到有依據的假設、操作、區辨輸入、觀察與事前三類判準；缺少技術判準時 agent 主動設計，未杜撰需求或觀測結果。
- 編號未占用、歷史未被未授權覆寫；環境、日期、指令、資料及證據位置可追溯。
- 八段紀錄、四狀態與任務完成判斷一致；觀察／推論、真實／模擬與限制分開。
- 結論不超過證據，未解阻決策不因本輪紀錄完成而推進。

## Quality Checks (best effort)
- 選擇最小可重現方式，指出足以改變結論的依賴與下一個所需證據。

## On Soft Fail
可恢復缺口採 `SOFT FAIL`，skill 處理狀態標 `INCOMPLETE`，保留可得依據並列出缺項；若繼續會產生誤導則 `BLOCKED`，停止依賴該缺口的操作或決策。這些處理狀態不替代實驗四狀態，也不表示假設失敗。

# Failure Handling
## Missing Context
先唯讀查官方文件／原始碼與可得情境，辨識已知問題與決策。缺假設、操作、區辨輸入或技術判準時主動提出有依據的設計，執行前固定判準，不以缺判準為由要求使用者填問卷。投入上限可依情境提出有限建議。只有查證後仍無法解決、且涉及重大業務需求／決策歧義、權限或投入界線時，列出必要澄清並將依賴動作標 `BLOCKED`；可保留安全的部分輸出為 `INCOMPLETE`。必要環境不可得則依 Execution Limitation 記錄限制，不杜撰需求或結果。

## Ambiguous Requirement
先用來源與已知決策解決技術設計分歧並說明選擇依據；不得因可自行設計的假設、操作或判準尚未提供就阻擋。只有仍無法解決的重大業務需求／決策歧義、權限或投入界線才澄清並停止依賴動作。非關鍵歧義可用明示假設繼續安全紀錄，列出限制，勿把假設當需求。

## Execution Limitation
權限、工具、環境或投入限制使執行不足時，記錄實際完成部分、原因、缺少證據與決策限制。尚未嘗試為「未執行」；已嘗試但不足分類為「無法判定」，不能誤記「失敗」。只有紀錄滿足完成語意才結束本輪；不得杜撰命令輸出、日期或成功結果。

# Boundaries
- 按需使用，不建立 runtime orchestration、必經 phase、每階段 gate 或自動 approval。
- 不自行取得外部操作、寫入、覆寫或發布權限；所需權限不足時說明限制。
- 實驗程式正式採用走原實作與審查流程；實驗完成不核准採用。影響已鎖定決策時提出證據與影響，交原變更流程，不自行重開決策。
